# DemandFlow 能力说明（设计阶段）

## 当前状态

- 阶段：Idea（设计阶段，尚未开发）
- 所属层级：Decision（第二层）
- 依赖：RouteFlow 和 NetworkFlow 标准化完成后启动

## 要解决的业务问题

小企业和供应链团队当前做需求判断时：
- 依赖经验，缺乏数据支撑
- 促销和季节性波动难以量化
- 缺货和积压同时存在
- 安全库存要么拍脑袋，要么照搬公式不管实际
- 补多少、什么时候补，缺少系统性建议

## 核心能力设计

DemandFlow 不应只是一个"上传 Excel 输出预测曲线"的工具。

完整链条应为：

历史需求 → 数据质量检查 → 需求预测 → 当前库存快照 →
缺货与积压风险识别 → 安全库存建议 → 补货数量与时间 →
多情景比较（乐观/基准/悲观）→ 人工确认 → 结果反馈与校准

## 输入

- 历史需求数据（SKU × 日期 × 数量）
- 当前库存水平
- 促销日历（可选）
- 节假日安排（可选）
- 供应商交期（可选，用于联动补货建议）
- 业务事件标注（可选，如断货、爆款）

## 输出

- 预测需求（含置信区间）
- 缺货风险清单（哪些 SKU 几号可能断货）
- 积压风险清单（哪些 SKU 库存过高）
- 安全库存建议
- 补货建议（补什么、补多少、什么时候到）
- 多情景对比表
- 需要人工确认的关键假设

## 可复用的公共对象

- Product/SKU
- Demand
- Inventory
- Order
- Supplier（补货联动）
- RiskEvent（缺货/积压风险）
- Recommendation

## 可调用的模块

- StockCheck（库存核对）
- SupplierScore（供应商评估，补货决策时参考）
- NetworkFlow（如需调整仓网支持预测变化）

## 可被调用的场景

- RouteFlow：预测到某区域需求增加 → 提前规划运力
- NetworkFlow：预测到结构性需求变化 → 重新评估仓网

## 当前边界

- V0.1 不接入实时销售数据
- 不替代企业 ERP 中的 MRP 模块
- 预测结果仅作为辅助判断，不自动触发采购
- 暂不支持多级 BOM 的衍生需求计算

## 开发前置条件

1. RouteFlow 和 NetworkFlow 标准化改造完成
2. 公共请求/结果格式稳定运行
3. 至少有 2-3 个真实或模拟数据集用于验证
